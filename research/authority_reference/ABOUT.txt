# Same-host owner authority and effect serialization experiment

**No central or off-host authority is required or permitted for host-ops or app-ops.** Each receiving machine must be able to authenticate, admit, remember, inspect, and recover its own accepted management work without contacting a manager, coordinator, witness, or shared authority. The per-owner `LocalOwner` SQLite WAL/FULL journal models that responsibility. The separate `LocalEffectTarget` SQLite file is a simulated **on-that-same-host, receiver-enrolled local target**, not an off-host service or remote fencing authority. It models only a target whose effect, replay reservation, and generation check fit one local transaction. This does not propose sharing SQLite WAL over a network.

The local test target has a distinct database to expose a journal/effect crash gap and allow same-host authoritative reconciliation. The target is not a second management authority: the receiver-local owner makes authorization and recovery decisions; the local target enforces its own mutation boundary. Both are maintained by the receiving computer. The application target need not have a database in real installations; native adapters must supply equivalent *verified* semantics or explicitly reject unsupported operations. `authorized=True` in the experiment is test-injected, independently authenticated local receiving-authority context, **never a wire permission**. Actual native enforcement must bind scopes, original accepted intent, principal and grant to OS-local authenticated IPC or other receiver-owned execution context and prevent privileged bypass.

## Reproduction

From the repository's clean locked workspace environment:

```sh
uv run --locked --all-packages --group dev python -m pytest -o addopts= -q research/authority_reference/test_reference_safety.py
```

See `research/authority_counterexamples/ABOUT.txt` for the deliberately failing, separate suite. These research checks do not enter maintained CI, qualify native operation behavior, or change public promises without an engineering and evidence review. They are not substitute native crash/power/permission/storage tests.

The experiment demonstrates owner-local admission while the *local target* is unavailable, atomic compare-and-swap claims, scoped epoch/request/effect identity, same-host replay, durable uncertain dispatch, positive local tombstones, a new-epoch owner restore without restored live activation, explicit target epoch handoff, and a checkpoint root that covers outcomes and is computed from a consistent snapshot. Claim IDs remain historically resolvable, but sessions recorded in the journal are not reactivated after restart; a fresh claim must fence the previous one.

Owner-local scope enrollment is stored in the owner journal independently of target availability. Unenrolled requests and claims are rejected even with test-injected authorization; explicit restore retains the enrollment and the checkpoint root binds its contents. The historical request-ID lookup has a unique secondary index so a missing-ID admission does not scan retained origins. These are research-model properties, not validated native enrollment, protected file custody, or a production growth proof.

The simulated target now requires durable `prepare_handoff` before `adopt_epoch`: preparation atomically invalidates old sessions and blocks new claims, effects, and no-effect tombstones until explicit adoption or abort. A lost preparation reply can be recovered by reopening the same local target, and abort does not revive prior sessions. This closes a *simulated* pre-adoption effect window, but not the owner-journal/target multi-database crash gap or any native physical-process gap. Native handoff needs independent cessation and protected mutation-path evidence; separate SQLite files do not provide a cross-file atomic transaction.

## Deliberate guarantee boundaries

- Full host clones, including the local target, can perform independent local effects. No software-only local algorithm can elect a globally unique physical writer among disconnected identical clones. Do not describe the per-host local fence as cross-machine exclusivity.
- Without an independently protected trusted *local* monotonic anchor (e.g. qualified hardware) or independently verified operator custody, a self-consistent owner+target rollback is undetectable. A caller-supplied `expected_manifest` is not itself anti-rollback evidence. The model does **not** require off-host anchoring; where the stronger guarantee is unavailable, recovery must not claim complete rollback detection.
- Full physical process exclusivity, OS kernel locking, service-manager process identity, authenticated IPC, filesystem alias/exclusion, credential custody, privilege controls, multi-step external effects, application-data checkpoint reconciliation, and power-loss durability are unimplemented. Even the model's copyable live session does not provide physical process exclusion.
- `close_absent` is positive only for the *simulated local database's* serialized effect path. For arbitrary services or files, no-effect evidence must include native effect-path coverage, cessation and continuing exclusion; missing a response is never evidence of absence.
- The model's manifest entails a linear scan and snapshot of retained work; it is not a qualified bounded native implementation. A production owner must meet the repository's growth, retained-custody, and check-evidence obligations.
- No off-host coordination is introduced by the model. If a proposed host-ops/app-ops mutation actually requires cross-machine exclusivity for an external shared resource, do not route the owner authority through a coordinator: reject that scope under the local-only contract or qualify an independently defined application-specific resource protocol without making it a prerequisite for local host/app owner authority.
